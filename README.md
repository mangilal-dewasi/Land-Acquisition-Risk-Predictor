# Land Acquisition Risk Predictor

A decision-support application for assessing potential land-acquisition delays in infrastructure projects. It combines a React + TypeScript dashboard with a Python/FastAPI backend that serves scikit-learn classification and regression models.

> **Important:** This application is a decision-support prototype, not a legal or administrative authority. Predictions depend on the dataset and modelling assumptions described below; they should not be treated as guaranteed project outcomes.

## Overview

The application accepts project characteristics such as project type, state, acquisition area, affected families, compensation disputes, environmental clearance, litigation, public-hearing completion, rehabilitation progress, and administrative delay.

It provides:

- A project risk assessment with an estimated delay probability and risk tier.
- An estimated schedule-overrun duration and a range.
- Engineered indicators for displacement density, legal friction, and statutory readiness.
- Feature-level explanations showing how input values move the prediction relative to a neutral baseline.
- A historical project registry, scenario comparison, and model-validation views.
- JSON export of an assessment.

The frontend can calculate a client-side estimate when the Python API is unavailable. When the API is available, its model prediction and evaluation results are used.

## Features

- **Risk assessment:** evaluates project inputs and returns a delay probability, binary delayed/not-delayed result, and risk category.
- **Delay forecast:** estimates schedule overrun in days and provides a range around the estimate.
- **Engineered features:** calculates displacement density, legal friction index, and statutory readiness gap.
- **Explainability:** provides baseline-relative feature contributions. These are not SHAP values.
- **Project registry:** loads and parses the CSV dataset for browsing and analysis.
- **Scenario comparison:** allows users to save, compare, reload, and remove assessment scenarios in the current browser session.
- **Model validation:** displays model evaluation information generated by the Python training pipeline.
- **Assessment export:** downloads the current assessment as a JSON file.

## Dataset

The supplied CSV contains **2,500 project records** and the following columns:

| Column | Description |
|---|---|
| `project_id` | Project identifier |
| `project_type` | Infrastructure project category |
| `region` | State/region |
| `region_size_hectares` | Acquisition area in hectares |
| `affected_families_count` | Number of affected families |
| `compensation_disputed_flag` | Whether compensation is disputed |
| `environmental_clearance_status` | Clearance status |
| `litigations_count` | Number of litigations |
| `public_hearing_completed` | Whether the public hearing is completed |
| `rehabilitation_progress_pct` | Rehabilitation progress percentage |
| `bureaucratic_delay_days` | Administrative delay in days |
| `target_delayed` | Binary classification target |

### Dataset location

Place the CSV at:

```text
public/data/dataset.csv
```

The frontend accesses it at:

```text
/data/dataset.csv
```

Because Vite serves files inside `public/` at the site root, the CSV can be fetched directly by the browser. **This makes the dataset publicly downloadable. Do not put confidential, personal, or restricted data in this folder.**

The Python training script reads the same CSV from the filesystem. Update `CSV_PATH` in `ml/train_model.py` to point to the new location:

```python
CSV_PATH = os.path.join(
    os.path.dirname(os.path.dirname(os.path.abspath(__file__))),
    "public",
    "data",
    "dataset.csv",
)
```

Also update the frontend URL constant in `src/App.tsx`:

```typescript
const DATASET_URL = '/data/dataset.csv';
```

No additional dataset API endpoint is required for this public-file arrangement. The existing `/api` Vite proxy is used for backend prediction and evaluation requests.

## Machine Learning Pipeline

The training and inference code is in `ml/`.

### Feature engineering

`engineer_features()` adds the following features:

| Engineered feature | Calculation |
|---|---|
| Displacement density | Affected families divided by acquisition area |
| Legal friction index | Litigation count multiplied by compensation-dispute flag |
| Statutory readiness gap | Encoded environmental-clearance status plus incomplete-hearing indicator |

The preprocessing pipeline imputes missing numeric values using the median and scales numeric features. Categorical values are imputed using the most frequent value and one-hot encoded.

### Classification

The training script benchmarks:

1. Logistic Regression
2. Random Forest Classifier
3. Gradient Boosting Classifier
4. Platt-calibrated Gradient Boosting Classifier

The calibrated Gradient Boosting model is saved as the primary classifier:

```text
models/calibrated_delay_classifier.pkl
```

The classification target is the dataset's `target_delayed` column.

### Delay-days regression

A Random Forest Regressor is trained to estimate delay days and saved as:

```text
models/delay_days_regressor.pkl
```

**Target-generation note:** The current training code creates the regression target using the `synthesize_delay_days()` function. It is calculated from input factors and the `target_delayed` label; it is not read from an independently observed delay-days column in the supplied CSV. Consequently, regression metrics measure performance against this generated target, not against independently recorded actual delay durations.

```cmd
.venv\Scripts\activate.bat
```

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Ensure the CSV exists at:

```text
public/data/dataset.csv
```

Then confirm that `CSV_PATH` in `ml/train_model.py` and `DATASET_URL` in `src/App.tsx` match the paths shown in the [Dataset](#dataset) section.

## Run the Application

### Recommended: start both servers

From the project root, with the Python virtual environment activated:

```bash
python run_local.py
```

The launcher:

1. Checks whether the classifier model file exists and trains models if it does not.
2. Starts FastAPI at `http://127.0.0.1:8000`.
3. Starts the Vite development server at `http://localhost:3000`.

Open:

```text
http://localhost:3000
```

Stop the launcher with `Ctrl+C`.

The FastAPI startup routine also checks for all three model artifacts and runs the training pipeline if any are missing.

### Train the models manually

Run this when you want to retrain the models:

```bash
python -m ml.train_model
```

Training writes the model files and evaluation JSON into `models/`.

### Run the services separately

**Terminal 1 — Backend:**

```bash
uvicorn ml.server:app --reload --host 127.0.0.1 --port 8000
```

**Terminal 2 — Frontend:**

```bash
npm run dev
```

The Vite development server proxies requests beginning with `/api` to the FastAPI server at `http://127.0.0.1:8000`.

### Build the frontend

```bash
npm run build
```

Vite writes the production frontend into `dist/`.

To serve that build through FastAPI, build the frontend first and then start the backend:

```bash
uvicorn ml.server:app --host 127.0.0.1 --port 8000
```

The FastAPI application mounts `dist/` at `/` when that directory exists. Open `http://127.0.0.1:8000`.

## API Reference

The FastAPI application is defined in `ml/server.py`.

Interactive API documentation is available at:

```text
http://127.0.0.1:8000/docs
```

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/api/health` | Checks the API and ensures model artifacts are loaded |
| `GET` | `/api/evaluation` | Returns the saved model evaluation suite |
| `POST` | `/api/predict` | Generates a prediction for the supplied project inputs |

### Prediction request example

```json
{
  "project_type": "Highway",
  "region": "Madhya Pradesh",
  "region_size_hectares": 240,
  "affected_families_count": 850,
  "compensation_disputed_flag": 0,
  "environmental_clearance_status": "Approved",
  "litigations_count": 1,
  "public_hearing_completed": 1,
  "rehabilitation_progress_pct": 60,
  "bureaucratic_delay_days": 45
}
```

The API validates the categorical values against the allowed options defined by the `ProjectInput` model in `ml/server.py`.

The prediction response includes the estimated delay probability, delayed/not-delayed flag, risk tier, engineered feature values, delay-days estimate and range, and baseline-relative feature contributions.

## Model Artifacts

The training pipeline creates:

| File | Purpose |
|---|---|
| `models/calibrated_delay_classifier.pkl` | Calibrated classifier used for delay-risk probability |
| `models/delay_days_regressor.pkl` | Random Forest regression pipeline for estimated delay days |
| `models/evaluation_metrics.json` | Classification, calibration, learning-curve, feature-importance, and regression evaluation data |

The repository's `.gitignore` currently excludes the `models/` directory. If model files are not committed, a fresh clone must train them before the backend can make predictions. The dataset must be present for training to succeed.

Only load pickle/joblib model files from trusted sources.

## Evaluation and Interpretation

The training pipeline records metrics including:

- Accuracy, precision, recall, F1 and F2
- ROC-AUC and PR-AUC
- Brier score
- ROC curve points
- Calibration bins
- F1/F2 threshold search
- Learning-curve values
- Permutation importance
- Regression MAE, RMSE and R²

The API's feature contributions are computed by replacing one input at a time with a predefined neutral baseline and measuring the change in predicted probability. The values are normalized for display. They are a model-agnostic baseline comparison, **not SHAP explanations or causal effects**.

## Deployment Notes

- The CSV in `public/data/` is served as a public static file and can be downloaded by visitors.
- The FastAPI backend and its model artifacts must be deployed wherever backend predictions are required.
- A static-only frontend can use its client-side TypeScript prediction and evaluation fallback, but that is not the same as running the trained Python models.
- Ensure the deployed backend has the required model artifacts or can access the dataset and dependencies to train them.
- Review CORS settings before public deployment. The current backend allows all origins and is configured for local development; production deployments should restrict origins to the actual frontend domain.
- Do not expose private datasets, credentials, or environment secrets in the repository.

## Limitations

- Predictions are estimates based on the supplied dataset and model assumptions; they are not guarantees.
- The supplied dataset has 2,500 records, but the README does not claim that these represent every region or project type.
- The regression target is synthetically generated by the current training code, rather than supplied as observed actual delay days.
- Feature contribution values describe changes relative to a selected baseline and should not be interpreted as causal explanations.
- The frontend fallback is a separate TypeScript implementation and may not produce identical outputs to the Python models.
